# ASSET-1 · 결정 로그 (DECISIONS)

자산관리 탭 설계 인터뷰(2026-09-28) 결과. D31~D46은 같은 날 스펙 검토(구멍 점검)에서 추가·보완한 결정. 사용자 대면 동작은 [`PRODUCT.md`](./PRODUCT.md),
구현 기준은 [`TECH.md`](./TECH.md) / [`tech/01-data-model.md`](./tech/01-data-model.md).
**구매관리(PURCHASE-1) 담당자와 조율이 필요한 사항은 [`COORDINATION.md`](./COORDINATION.md)에 따로 모았다.**

## 배경 — 왜 PURCHASE-1 설계를 그대로 쓰지 않나

PURCHASE-1은 "구매 유닛 = 자산"을 전제로, 자산관리 탭은 `asset_units` 위에 배정(`asset_assignments`)만
얹는 구조로 스케치돼 있었다(`specs/PURCHASE-1/DECISIONS.md` "구매관리·자산관리 관심사 분리").

그런데 실제 업무에서는 **구매품 전부가 사내 자산이 아니다.** 고객사 제품을 대리 구매(재판매)하는 경우가
있어, 구매 기록 중 일부만 자산이다. 또 구매 기록 없이 이미 보유 중인 장비도 자산으로 관리해야 한다.
그래서 자산을 **별도 컬렉션(`assets`)** 으로 두고, 구매 유닛은 선택적으로 "가져오는" 원천이 된다.

| D40 | 팀원 이름 변경 전파 | 팀원 이름을 고치면 그 사람이 **지금 쓰는** 자산의 현재 사용자 이름도 갱신. 과거 이력의 이름은 당시 이름(스냅샷) 유지 | 목록용 비정규화 필드가 옛 이름으로 남는 것 방지 |
| D41 | 유형 변경 불가 | 자산의 유형(SW/HW/EDU)은 등록 후 수정 불가(번호 접두어와 일치해야 함). 잘못 등록했으면 가져오기 취소/폐기 후 재등록 | 번호 `SW-…`인데 유형이 HW인 불일치 방지 |
| D42 | 비밀번호 수정 규칙 | 수정 폼에서 비밀번호 칸을 비워두면 **기존 값 유지**. 삭제는 별도 [비밀번호 삭제] 버튼 | 폼이 비밀번호를 미리 채울 수 없어서, "빈 값 = 삭제"면 실수로 지워짐 |
| D43 | 키 미설정 시 통째로 실패 | 암호화 키가 없을 때 비밀번호를 포함한 등록·수정 요청은 **전체 실패**(`501 SECRET_KEY_MISSING`). 비밀번호 없는 요청은 정상 동작 | 다른 항목만 저장되고 비밀번호가 조용히 빠지는 일 방지 |
| D44 | 비밀번호 열람 기록 | [보기]/[복사]마다 누가·언제·어떤 자산을 열람했는지 저장. 조회 화면은 범위 밖 | 사고 시 추적 가능해야 함. 감사로그 UI 없이도 데이터는 남겨둠 |
| D45 | 날짜 기준 = KST | "오늘"·"올해"는 모두 한국 시간 기준 — 만료 배지, 기본 날짜, 채번 연도, 미래 날짜 검사 | 서버(Vercel)는 UTC라 1/1 09시 전 등록 시 전년도 번호가 붙는 등 어긋남 |
| D46 | 그룹관리자 명단 범위 | 그룹관리자는 팀원 명단에서 **자기 그룹 팀원만** 봄. 다른 그룹에서 옮겨온 팀원의 이전 이력도 보이되 D37 규칙 적용 | 기존 그룹 스코프 원칙 유지 |
