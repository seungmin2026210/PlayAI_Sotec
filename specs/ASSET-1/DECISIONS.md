# ASSET-1 · 결정 로그 (DECISIONS)

자산관리 탭 설계 인터뷰(2026-09-28) 결과. 사용자 대면 동작은 [`PRODUCT.md`](./PRODUCT.md),
구현 기준은 [`TECH.md`](./TECH.md) / [`tech/01-data-model.md`](./tech/01-data-model.md).
**구매관리(PURCHASE-1) 담당자와 조율이 필요한 사항은 [`COORDINATION.md`](./COORDINATION.md)에 따로 모았다.**

## 배경 — 왜 PURCHASE-1 설계를 그대로 쓰지 않나

PURCHASE-1은 "구매 유닛 = 자산"을 전제로, 자산관리 탭은 `asset_units` 위에 배정(`asset_assignments`)만
얹는 구조로 스케치돼 있었다(`specs/PURCHASE-1/DECISIONS.md` "구매관리·자산관리 관심사 분리").

그런데 실제 업무에서는 **구매품 전부가 사내 자산이 아니다.** 고객사 제품을 대리 구매(재판매)하는 경우가
있어, 구매 기록 중 일부만 자산이다. 또 구매 기록 없이 이미 보유 중인 장비도 자산으로 관리해야 한다.
그래서 자산을 **별도 컬렉션(`assets`)** 으로 두고, 구매 유닛은 선택적으로 "가져오는" 원천이 된다.

## 확정 사항

| # | 결정 | 내용 | 이유 |
|---|---|---|---|
| D1 | 자산 = 별도 컬렉션 | `assets` 컬렉션. 구매 유닛에서 **선택적으로 가져오기** + 구매 기록 없는 **직접 등록** 둘 다 허용 | 재판매(대리구매)품은 자산이 아님. 구매 이전 보유 장비도 관리 대상 |
| D2 | 가져오기 = 복사 + 링크 | 가져오는 시점 값(구매일·금액·구매처·견적번호·상품명·키/계정·만료일)을 **복사**하고 `source_unit_no` 링크 유지. 이후 수정은 자산관리에서 독립적으로 | 구매 기록(무엇을 샀나)과 자산 기록(지금 어떻게 쓰나)의 수정 주체가 다름 |
| D3 | 유형 자동 결정 | 가져올 때 SW/HW/EDU는 구매 상품의 `asset_category`를 그대로 따름 | 이중 입력 방지 |
| D4 | 1회만 가져오기 | 한 구매 유닛은 자산 1건으로만 가져올 수 있음. 구매 목록에 "자산 등록됨(SW-26-012)" 표시 | 중복 자산 방지 |
| D5 | 자산 1건 = 사용자 1명 | 10석 구독 = 자산 10건. 교육은 **인프런 ID 1개 = 강의 1개 = 자산 1건** | "누가 어떤 시리얼/계정을 쓰나"와 이력이 1:1로 맞음 |
| D6 | 번호 체계 | `{SW\|HW\|EDU}-{YY}-{NNN}` (예: `HW-23-004`). 유형별·연도별 독립 순번, 3자리(연·유형당 999 초과 시 409) | 몇 년도 구매 자산인지 번호로 구분 |
| D7 | 번호 연도 = 구매일 연도 | 구매일이 없으면 등록 시점 서버 연도. **구매일을 나중에 고쳐도 번호는 안 바뀜** | "언제 샀나"가 목적. 번호는 한 번 붙으면 영구 |
| D8 | 영구 결번 | 폐기돼도 번호 재사용 없음, 시퀀스는 증가만 | QUOTE-1·PURCHASE-1과 동일 원칙 |
| D9 | 소분류 = 고정 목록 | 드롭다운 + "기타". 목록은 `config.py` 한 곳. SW: 라이선스/AI 구독/기타, HW: 노트북/모니터/마우스/키보드/허브/라우터/기타. EDU는 소분류 없음 | 표기 차이로 필터·집계 갈라짐 방지 |
| D10 | 사람 = 팀원 명단 | `members` 컬렉션(이름·사번·그룹·재직여부). 배정은 명단에서 선택. 퇴사자는 삭제 없이 "퇴사" 표시 | 자유 입력은 "김철수"/"김 철수"로 갈라져 사람별 조회가 깨짐 |
| D11 | 계약번호 = 임시 자유입력 | 계약관리 미구현 → 자산에 `contract_no` 텍스트 칸. 계약관리 생기면 링크로 교체 | CLAUDE.md "미정 항목은 눈에 띄고 바꾸기 쉬운 임시값" |
| D12 | 날짜 2층 구조 | 자산: 구매일, **유효기간 시작·종료**(라이선스/구독 기간). 이력: 사람별 **사용 시작일·종료일** | 둘 다 필요(인터뷰 Q5) |
| D13 | SW 버전 = 현재 값만 | 버전 변경 이력은 남기지 않음 | 이력은 "누가 썼나"에만 |
| D14 | 교육 = 배정 구조 재사용 | "제가 듣고 있어요" = 현재 사용자 배정. 수료 여부는 관리 안 함. 중복 방지 = **동시 사용 방지**만(중복 구매 경고 없음 — 강의명 검색으로 충분) | SW/HW와 동일 모델로 단순화 |
| D15 | 비밀번호 저장 | SW·EDU 계정 비밀번호 **저장함**. DB엔 암호화(키는 서버 환경변수), 화면엔 마스킹, **전체관리자만 보기/복사**. 목록·키워드검색·엑셀에는 절대 포함 안 함 | 업무상 필요. 평문 저장은 보안사고 위험 |
| D16 | 비밀번호 열람 확장 지점 | 열람 권한 판정을 `deps.py` 한 함수로 격리. **나중에 팀원 로그인이 생기면 "그 자산을 현재 쓰고 있는 본인"에게도 허용**할 수 있게(미구현) | 인터뷰 Q19 요청 |
| D17 | 사용자 변경(이관) | "사용자 변경" 한 번 = 이전 사용자 종료 + 새 사용자 시작(원자적). 회수·배정 단독 동작도 제공 | 실제 업무 흐름 |
| D18 | 날짜는 직접 입력 | 사용 시작/종료일은 관리자가 입력(기본값 오늘). 서버 시각 아님 | 실제 인계일과 입력일이 다름 |
| D19 | 동시 배정 금지 | 사용 중인 자산에 추가 배정 시 409 | 1자산 1사용자(D5), 교육 중복 수강 방지(D14) |
| D20 | 이력 수정 허용 | 전체관리자는 이력의 **날짜·비고만** 수정 가능(사람 변경 불가). 수정자·수정시각 기록 | 수기 날짜 입력 실수가 흔함. 감사로그 UI는 범위 밖 |
| D21 | 상태값 | 미사용(`IDLE`) / 사용 중(`IN_USE`) / 폐기(`DISPOSED`, soft delete). **만료는 상태가 아니라 배지**(유효기간 종료일 경과 시 자동 표시). 30일 내 만료는 "만료 임박" 배지 | 만료돼도 갱신 전까지 계속 쓰는 경우 있음 |
| D22 | 자동 회수 없음 | 만료돼도 사용자를 자동으로 빼지 않음 | PURCHASE-1 원칙과 동일 |
| D23 | 권한 | 구매관리와 동일: 전체관리자만 등록·수정·배정·폐기·명단관리. 그룹관리자는 자기 그룹 조회만(타 그룹 상세 = 404) | 기존 원칙 유지 |
| D24 | 그룹 판정 = 현재 사용자 소속 | 사용 중이면 **현재 사용자의 소속 그룹**, 미사용이면 등록 시 지정한 그룹 | 그룹관리자의 관심사는 "우리 팀원이 뭘 쓰나" |
| D25 | 사용자별 탭 | 팀원별 SW/HW/EDU 현재 사용 개수, 클릭 시 현재 자산 + 과거 이력. 명단 관리(등록·퇴사처리)도 이 탭 안에 | 메뉴 증가 방지 |
| D26 | 검색 | 드롭다운 필터: 소분류·사용자·그룹·상태·만료여부·구매연도. 키워드: 자산번호·품명·시리얼/라이선스키·계정ID·제조사/모델·강의명·견적번호·계약번호·비고. 기본은 폐기 숨김 | 인터뷰 Q22 |
| D27 | 엑셀 다운로드 | 현재 필터 적용된 목록 그대로, 비밀번호 제외 | 기존 엑셀 관리 업무 대체 |
| D28 | 대시보드 연동 | **갱신 캘린더 · 다가오는 갱신 일정 · 갱신 임박(D-30) KPI** 3개만 실데이터. 갱신 임박 자산 표(예상비용)·자산 현황 표는 목업 유지 | 유효기간 종료일만으로 만들 수 있는 것부터 |
| D29 | 캘린더 대상 | 유효기간 종료일이 있는 자산(SW·EDU, HW는 입력한 경우만), 폐기 제외. **같은 날·같은 품명은 한 줄로 묶음**("Copilot 구독 10건"). 클릭 시 해당 자산 목록으로. 그룹 스코프 적용 | 10석 = 10건이라 안 묶으면 캘린더가 도배됨 |
| D30 | 메뉴 위치 | 사이드바 "계약관리" 그룹 하위에 **자산관리(`/assets`)** 추가 → 화면 내 탭 **SW / HW / 교육 / 사용자별** | 인터뷰 확인 |

## 임시 결정 (인터뷰에서 직접 다루지 않음 — 구현 전 확인 권장)

인터뷰 범위 밖이라 합리적 기본값으로 정해뒀다. 실사용 전 사용자 확인 후 확정.

| # | 임시 결정 | 격리 위치(예정) |
|---|---|---|
| P1 | 사용 중인 자산은 바로 폐기 불가 → 먼저 회수(`409 ASSET_IN_USE`) | `services/asset_status.py` |
| P2 | 팀원 퇴사 처리 시 사용 중 자산이 있으면 **경고만** 하고 자동 회수 안 함(D22와 일관). 퇴사자에겐 신규 배정 불가(`409 MEMBER_INACTIVE`) | `routers/members.py` |
| P3 | 팀원 소속 그룹이 바뀌면, 그 사람이 쓰는 자산의 조회 그룹(`scope_group_code`)도 같이 갱신 | `services/members.py` |
| P4 | 이력 날짜 수정 시 같은 자산의 다른 이력과 기간이 겹치면 거부(`400 VALIDATION_ERROR`) | `services/asset_assignment.py` |
| P5 | 사번은 필수·유일, 팀원 문서 ID로 사용 | `tech/01-data-model.md` §4 |
| P6 | 목업으로 남는 대시보드 위젯 2개에 "준비 중" 표시 여부 | `frontend/src/pages/Dashboard.tsx` |
| P7 | 소분류 초기 목록(D9)의 구체 항목 | `config.py: ASSET_SUBCATEGORIES` |
