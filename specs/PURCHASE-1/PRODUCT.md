# PURCHASE-1 · 구매관리 (제품 스펙)

> 이 문서는 **구매관리 탭**만 다룬다("뭘, 언제, 얼마에 샀는지"). 배정("누구에게 줬는지")은
> 자산관리 탭 소관이며 별도 스펙/구현으로 진행한다([`DECISIONS.md`](./DECISIONS.md) "구매관리·자산관리
> 관심사 분리"). 아키텍처/데이터 모델 기준은 [`TECH.md`](./TECH.md).

## 목적

지금까지 엑셀로 수기 관리하던 SW/HW/교육자산 구매 기록(상품, 수량, 구매일자, 구매처, 라이선스 키)을
전산화한다. 이 탭에서 부여한 고유번호를 자산관리 탭이 그대로 참조해 배정 화면을 연다.

## 범위

**포함**
- 상품 마스터 등록/조회/수정(이름·벤더·사용여부)
- 자산 유닛(개별 구매 1건) 등록 — 상품 선택 시 자동 채번(`상품명-순번`)
- 유닛 목록 조회(상품별/상태별/그룹별 필터)
- 유닛 폐기(soft delete, 물리 삭제 없음)
- 견적서에서 연동해 구매하는 경우, 해당 견적서 자동 잠금

**범위 밖(다음 단계)**
- 배정/반납(자산관리 탭, 팀원 구현)
- 신청→승인 흐름(일반 사용자 로그인 필요, 뒤로 미룸)
- 예산 연동

## 사용자 · 권한

QUOTE-1과 동일한 두 역할을 그대로 쓴다(새 역할 추가 없음).

| 역할 | 상품 마스터 | 유닛 등록/폐기 | 유닛 조회 |
|---|---|---|---|
| 전체관리자(SUPER_ADMIN) | CRUD | 가능 | 전체 |
| 그룹관리자(GROUP_MANAGER) | 조회만 | 불가(403) | 본인 그룹만 |

그룹관리자가 다른 그룹 유닛 상세에 직접 접근하면 QUOTE-1과 동일하게 **404**(존재 은닉)로 응답한다.

## 핵심 시나리오

1. **상품 등록**: 전체관리자가 "인텔리제이 / JetBrains / SW"처럼 상품을 미리 등록해둔다. 자유
   텍스트 입력이 아니라 이 목록에서 선택하는 방식 — 표기가 갈라져 채번이 꼬이는 걸 방지한다.
2. **구매 유닛 등록**: 상품을 고르고 구매일자·구매처·금액을 입력하면 `인텔리제이-001`처럼
   유닛번호가 자동으로 매겨진다. SW는 유닛 타입(키/계정)과 키 값을, HW는 비워둔다.
3. **견적 연동 구매**: 승인된 견적서에서 이어서 구매하는 경우 해당 견적을 선택하면, 유닛 등록과
   동시에 그 견적서가 잠긴다(이후 수정 불가 — QUOTE-1의 기존 잠금 매커니즘 실연동).
4. **목록 조회**: 상품별/상태별(재고·배정됨·만료)/그룹별로 필터링해서 본다.
5. **폐기**: 라이선스가 만료되거나 더 이상 안 쓰는 자산을 "폐기" 처리하면 상태만 `만료`로
   바뀌고 번호는 영구 보존된다(재사용 안 함). **자동 반납은 하지 않는다** — 아직 배정 중인
   자산의 반납은 자산관리 탭에서 사람이 직접 처리한다.

## 데이터 항목

상세 필드 정의는 [`TECH.md`](./TECH.md) § 데이터 모델. 화면에 노출되는 사용자 대면 용어만 요약:

| 항목 | 설명 |
|---|---|
| 상품 | 미리 등록된 상품 마스터에서 선택 |
| 유닛번호 | 자동 채번, 수정 불가 |
| 구매일자 / 구매처 / 금액 | 직접 입력 |
| 유닛 타입 | 키 / 계정 (SW만 선택, HW는 해당 없음) |
| 키 값 | 실제 키 문자열 또는 배정용 계정 값 |
| 만료일 | 선택 입력, 비우면 무기한 |
| 상태 | 재고 / 배정됨 / 만료 — 직접 바꾸지 않음(배정·폐기 액션으로만 갱신) |

## 채번 규칙

`{상품명}-{순번}`(예: `인텔리제이-001`), 상품별 독립 시퀀스. 결번(폐기된 번호)은 재사용하지
않는다 — QUOTE-1의 관리번호 결번 원칙과 동일.

## 화면 구성 (구매관리 탭)

- 상품 마스터 목록/등록/수정 (간단한 모달 또는 인라인 폼)
- 구매 유닛 목록 (필터: 상품/상태/그룹, 페이지네이션)
- 구매 유닛 등록 폼
- 구매 유닛 상세 (폐기 버튼 포함)

기존 `frontend/src/design/`(AppShell, Sidebar, tokens)과 `/purchase` 라우트를 그대로 쓴다 — 새
디자인 시스템을 만들지 않는다.

## 예외 처리

| 상황 | 응답 |
|---|---|
| 사용 중지된 상품으로 유닛 등록 시도 | `409 PRODUCT_INACTIVE` |
| 이미 폐기된 유닛을 다시 폐기 | `409 ALREADY_RETIRED` |
| 그룹관리자가 등록/폐기 시도 | `403 FORBIDDEN_ROLE` |
| 존재하지 않는 상품/유닛 | `404 NOT_FOUND` |
| 그룹관리자가 타 그룹 유닛 상세 접근 | `404 NOT_FOUND`(존재 은닉, 403 아님) |

## 미정 사항

- 상품 마스터 조회를 그룹관리자에게도 허용할지(현재: 허용, 조회만) — 실사용하면서 재검토.
- 일반 사용자(USER) 로그인 도입 시점 — 신청/승인 흐름을 언제 붙일지는 별도 논의.
