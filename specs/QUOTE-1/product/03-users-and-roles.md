# 03. 사용자 및 권한

## 3.1 역할 정의

| 역할 | 권한 | 대상자 |
|---|---|---|
| 전체관리자 (`SUPER_ADMIN`) | 전체 그룹 견적 조회, 등록, 수정, 취소, 삭제, 승인, 반려 | 수진 프로, 선정 프로, 박승철 그룹장(대체인력) |
| 그룹관리자 (`GROUP_MANAGER`) | 본인 그룹 견적 **조회 전용** (등록/수정/취소/삭제/승인/반려 불가) | 각 그룹 담당자 |

**❓ 미정 (open-1)**: 그룹관리자 권한은 이번 단계에서는 조회 전용으로 고정하되, 추후(2단계 이후) 등록 권한 등으로 확장 예정. 확장 시점·범위 미정.
→ 구현: 권한 판정을 `app/deps.py`의 정책 함수 1곳에 모아, 확장 시 이 함수만 수정.

> 표의 담당자명은 실명 기재 상태. 문서 공유·배포 범위에 따라 직책/역할명 대체 검토 필요.

## 3.3 인증 방식 (이번 범위)

- 실제 인증 로직·API 연동은 만들지 않음 (범위 외, 향후 출퇴근 프로그램 API 연동 예정).
- **개발/테스트 단계**: 하드코딩 계정(소수)으로 로그인 시뮬레이션.
- **실사용 전환 시**: 전체관리자 및 각 그룹관리자에게 **개별 ID/PW를 각각 부여** — 계정 공유 금지. "누가 승인/반려/수정했는지"가 실제 인물로 식별되어야 이력 소실 방지(1.2 목적)가 의미를 가진다. 여러 명이 계정 1개(예: Admin)를 공유하는 방식은 사용하지 않는다.
- 계정 정보(ID/PW/역할/소속 그룹 매핑)는 **상수 파일 1곳에만** 정의(`app/config.py` `ACCOUNTS`)하고 코드 곳곳에 흩뿌리지 않는다.

| ID | PW | 역할 | 소속 그룹 |
|---|---|---|---|
| Admin | 1234 | 전체관리자 | 전체(그룹 제한 없음) |
| test1 | 1234 | 그룹관리자 | **❓ 미정 (open-2)** — 임시로 `A` 지정, 협의 후 확정 |

## 3.4 역할별 화면 차이

기본 원칙:

- **그룹관리자 화면**: 등록/수정/취소/삭제/승인/반려 버튼 전체 숨김. 목록·상세는 본인 그룹 데이터만 노출.
- **전체관리자 화면**: 전체 그룹 데이터 + 모든 액션 버튼 노출.

**❓ 미정 (open-3)**: 화면별 상세 스펙(버튼 배치, 숨김 처리 방식, 와이어프레임) 미정. 위 원칙 기준으로 착수.
→ 구현: 프론트에서 `user.role` 기준 조건부 렌더링. 서버에서도 동일 권한 재검증(클라이언트 신뢰 안 함).
